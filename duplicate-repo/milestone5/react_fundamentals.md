# Understanding Components & Props Reflection 

## Why are components important in React?
Components are important in React because they allow developers to break down a user interface into smaller, reusable and manageable parts. This reduces code duplication and makes the code easier to understand, maintain and update. Components can also receive data through props, allowing the same component to display different content dynamically. 

This task helped me understand how components and props improve code reusability and flexibility in React.

# Handling State & User Input Reflection 

## What happens if we modify state directly instead of using setState?
Modifying state directly instead of using a state setter does not notify React that the state has changed. As a result, React may not re-render the component, causing the user interface to display outdated values. To observe this behaviour, I replaced setCount(count + 1) with count = count + 1 in the counter component. This caused an error because count was declared as a constant. When I clicked the increment button, the displayed count did not update.

This task helped me understand the importance of using state setters to ensure that changes in state are reflected dynamically in the user interface.

# Working with Lists & User Input Reflection 

## What are some common issues when working with lists in React?
1. Putting the key on the wrong element: The key should be assigned to the outermost element returned by .map(), rather than an element nested inside it.
2. Generating keys during rendering: Using Math.random() or generating a new UUID inside .map() causes React to recreate list elements on every render instead of reusing them.
3. Duplicate keys: Using the same key for multiple items can cause unexpected rendering behaviour. Each item should have a unique and stable key.
4. Mutating the array directly: Using items.push(x) followed by setItems(items) may prevent React from re-rendering because the array reference remains unchanged. Instead, a new array should be created using setItems([...items, x]).
5. Forgetting the empty state: An empty list can make the interface appear incomplete or confusing. Displaying a short message when no items are available can improve the user experience.

# Navigation with React Router Reflection 

## What are the advantages of client-side routing?
- Faster navigation: Only the necessary components are rendered or updated instead of reloading the entire page.
- Improved performance: Lazy loading can be used to load components only when needed, reducing the initial loading time.
- Improved user experience: Animations and transitions can be implemented when switching between different components, making navigation smoother.
- Seamless single-page application experience: Different views are displayed dynamically without refreshing the current page or loading a separate HTML document.

# Understanding React Hooks useEffect Reflection 

## When should you use useEffect instead of handling logic inside event handlers?
useEffect should be used when a component needs to synchronise with external systems, such as managing timers, subscriptions, event listeners or fetching data in response to changes in state or props. Event handlers are more suitable when an action is triggered by a specific user interaction, such as clicking a button or submitting a form.

## What happens if you don’t provide a dependency array?
If a dependency array is not provided, useEffect runs after every committed render of the component, which can result in unnecessary effect executions. An empty dependency array ([]) allows the effect to run on mount, while an array containing specific dependencies allows the effect to run on mount and whenever those dependencies change.

## How can improper use of useEffect cause performance issues?
- Unnecessary effect executions: Omitting the dependency array or using unstable dependencies can cause effects to run more frequently than necessary.
- Infinite rendering loops: Updating state inside an effect can cause continuous re-rendering if the state update repeatedly triggers the effect.
- Unnecessary API requests: Repeatedly fetching the same data can increase network usage and slow down the application.
- Memory leaks: Failing to implement appropriate cleanup functions can leave timers, subscriptions or event listeners active even after a component unmounts.

# Optimizing Performance with useMemo Reflection 

## How does useMemo improve performance?
useMemo improves performance by caching the result of a calculation between renders. Instead of performing the calculation every time a component re-renders, React reuses the cached result if the dependencies have not changed. This reduces unnecessary computations and can improve application responsiveness, particularly when working with large datasets or computationally expensive operations.

## When should you avoid using useMemo?
- Simple calculations: When a calculation is inexpensive and can be performed quickly, the overhead of memoisation may outweigh its benefits.
- Frequently changing dependencies: If the dependencies change on every render, the calculation will still be performed repeatedly, reducing the benefits of memoisation.
- Unnecessary optimisation: Overusing useMemo can increase memory usage and code complexity without providing significant performance improvements.

## What happens if you remove useMemo from your implementation?
Without useMemo, the expensive calculation would run every time the component re-renders, even when its dependency remains unchanged. In my implementation, I included two buttons to demonstrate this behaviour. With useMemo, clicking the "Re-render Component" button updates the test count without repeating the expensive calculation, whereas clicking the "Increase List by 100" button changes the list size and triggers recalculation. If useMemo is removed, clicking either button would cause the expensive calculation to run again. Although the calculated result would remain the same when only the test count changes, unnecessary computations would be performed, potentially reducing performance.
