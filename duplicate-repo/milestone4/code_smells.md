# Identifying & Fixing Code Smells Reflection

## What code smells did you find in your code?
From my previous coding experience, I have encountered several common code smells, such as magic numbers, long functions, duplicate code, deeply nested conditionals, commented-out code and inconsistent naming. I also learned about the problems associated with large classes that handle too many responsibilities. These code smells can make code unnecessarily complex and difficult to understand, especially when working on larger projects or collaborating with other developers.

## How did refactoring improve the readability and maintainability of the code?
Refactoring improves readability and maintainability by simplifying complex logic, replacing hardcoded values with meaningful constants, breaking down large functions and classes into smaller components, removing unnecessary code, and using descriptive names. These changes make the code more organised and easier to understand. Reducing duplication and separating responsibilities also makes future updates easier without affecting unrelated parts of the code.

## How can avoiding code smells make future debugging easier?
Avoiding code smells makes debugging easier by allowing developers to understand the code and identify the source of an issue more quickly. Smaller, focused functions make it easier to isolate and test individual parts of the code, while meaningful names and simpler conditions make the logic easier to follow. Reducing code duplication also makes it easier to fix issues in one place rather than having to update the same logic in multiple locations.
